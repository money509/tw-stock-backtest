# 台股策略回測比較工具

比較「原版（ATR計算有bug）」跟「新版（ATR計算已修正）」這兩套邏輯，
用同一份歷史股價回測，看修正 ATR 公式對策略績效實際上造成多大差異。

兩個版本的**進場條件完全一樣**（均線多頭排列、跳空風控），差別只在停損/停利價位的計算方式，
所以績效差異可以完全歸因於 ATR 公式的修正，不會被其他因素干擾。

---

## 一、檔案說明

| 檔案 | 用途 |
|---|---|
| `engine.py` | 回測核心邏輯（跟 `main.py` 的策略邏輯保持一致） |
| `data_loader.py` | 從 Yahoo Finance 下載歷史股價，並存成本機快取 |
| `compare.py` | 主程式，跑兩種版本並輸出比較報告 |
| `requirements.txt` | 需要安裝的 Python 套件清單 |

## 二、怎麼在本機執行（最簡單、不用 GitHub）

如果你只是想先在自己電腦上跑跑看，**不需要建立 GitHub 專案**，照下面步驟做就好：

### 步驟 1：安裝 Python

如果電腦還沒有 Python，先到 https://www.python.org/downloads/ 下載安裝（3.10 版以上）。
安裝時記得勾選 **"Add Python to PATH"** 這個選項。

### 步驟 2：把這幾個檔案放進同一個資料夾

例如放到桌面的 `stock-backtest` 資料夾裡，確認 `engine.py`、`data_loader.py`、`compare.py`、
`requirements.txt` 都在同一層。

### 步驟 3：安裝套件

打開終端機（Windows 叫「命令提示字元」或 PowerShell，Mac 叫「終端機 Terminal」），
切換到那個資料夾，輸入：

```bash
cd 桌面/stock-backtest
pip install -r requirements.txt
```

### 步驟 4：執行回測

```bash
python compare.py
```

預設會抓「最近兩年」的資料。想指定期間可以加參數，例如：

```bash
python compare.py --start 2022-01-01 --end 2025-01-01
```

第一次執行會需要一點時間下載約 60 檔股票的歷史資料，之後重複執行會用本機快取，速度快很多。
如果想強制重新下載最新資料：

```bash
python compare.py --refresh
```

### 步驟 5：看結果

執行完會在同一個資料夾下產生一個 `results/` 資料夾，裡面有：

- `summary.txt`：兩版績效比較表格（交易次數、勝率、平均報酬、累積報酬、最大回撤）
- `trades_buggy.csv`：原版每一筆交易明細，可以用 Excel 打開
- `trades_correct.csv`：新版每一筆交易明細
- `equity_curve.png`：兩版權益曲線比較圖，用看圖檔軟體打開就能看到走勢對比

## 四、如何解讀報告裡的數字

| 指標 | 意義 |
|---|---|
| 交易次數 | 這段期間總共進出場幾次 |
| 勝率 | 賺錢的交易佔全部交易的比例 |
| 平均每筆報酬 | 每一筆交易平均賺/賠多少百分比 |
| 累積報酬 | 假設本金固定投入、連續做這些交易，總共累積賺/賠多少（不含資金運用效率） |
| 最大回撤 | 從最高點到最低點，資金曾經縮水過的最大幅度，數字越負代表風險越大 |

## 六、動能分數 x 部位大小：四種組合比較（進階）

除了ATR公式的比較，這裡再多提供一組比較：**動能分數公式**（原版 vs 加入成交量權重）
交叉 **部位大小規則**（固定2口 vs 依風險動態調整口數），一共4種組合。

這4種組合都是建立在「ATR已經修正過」的基礎上（因為那已經確認是對的），
這樣才能單純比較「動能分數」跟「部位大小」這兩個維度各自的影響，不會被ATR那個問題混在一起看不清楚。

### 4種組合分別是什麼

| 組合 | 動能分數 | 部位大小 |
|---|---|---|
| original + fixed2 | 現價/5日線 × 10（原版） | 固定買2口 |
| original + risk_based | 現價/5日線 × 10（原版） | 依風險金額動態換算口數 |
| volume_weighted + fixed2 | 原版分數 × 成交量權重 | 固定買2口 |
| volume_weighted + risk_based | 原版分數 × 成交量權重 | 依風險金額動態換算口數 |

**量能加權公式**：原本分數 × min(當日成交量 ÷ 20日均量, 2.0)。
用「封頂2倍」是為了避免單一天成交量異常暴增，把分數推得不合理的高。

**風險動態調整口數**：設定一個「每筆交易願意賠多少錢」的風險金額（預設NT$20,000），
用 風險金額 ÷ (進場價−停損價) ÷ 契約乘數 反推可以買幾口，且至少維持2口。
這樣波動小的股票可以買比較多口，波動大的股票口數會被限制在比較少，
是比「不管股票波動大小都固定買2口」更接近「風險平衡」的做法。

### 怎麼跑（跟前面ATR比較的方式一樣，用GitHub Actions最簡單）

1. 把 `sizing.py`、`compare_four_way.py`、`.github/workflows/backtest_four_way.yml`
   這三個檔案一樣用「Add file → Upload files」的方式加到你的GitHub倉庫
   （`sizing.py`、`compare_four_way.py` 放在跟 `engine.py` 同一層；
   `backtest_four_way.yml` 要放在 `.github/workflows/` 資料夾底下，
   上傳時檔名要打完整路徑 `.github/workflows/backtest_four_way.yml`）
2. 到 GitHub 網站的 **"Actions"** 分頁，這次選左邊的 **"Run Strategy Backtest (Score & Sizing)"**
3. 點 **"Run workflow"**，可以順便調整「每筆風險金額」跟「起始資金」這兩個參數，不改也可以直接用預設值
4. 等執行完成，一樣到 **"Artifacts"** 下載 `backtest-four-way-results`
5. 解壓縮後看：
   - `summary.txt`：4個組合的績效數字並排比較（交易次數、勝率、報酬率、新台幣損益、最大回撤）
   - `equity_curve_four_way.png`：4條權益曲線疊在一起看走勢差異
   - `trades_原版名稱__部位規則.csv`：每個組合各自的逐筆交易明細

### 重要提醒

`engine.py` 這次也一併更新了（多支援了動能分數跟部位大小的參數），
如果你之前上傳過舊版的 `engine.py`，記得**這次要用新版覆蓋掉**，不然新的比較程式會出錯或找不到參數。
`compare.py`（第一次ATR比較用的）我有特別確認過在新版 `engine.py` 下還是可以正常運作，不用擔心互相影響。

## 七、均值回歸雙向策略（新策略，取代原本的順勢突破邏輯）

在確認原本「均線突破」策略長期是虧損的之後，重新設計了一套完全不同性格的策略：
**均值回歸、高勝率、小賺小賠、多空雙向、全市場320檔股票期貨動態掃描**。

### 核心邏輯

- **做多**：RSI(14)跌破30 + 股價跌破布林通道下軌 + 股價仍在60日均線之上（避免真正結構性空頭誤觸發）
- **做空**：條件完全對稱，RSI站上70 + 站上布林上軌 + 股價仍在60日均線之下
- **出場**：目標價是布林中軌(20日均線)，停損是通道邊緣再擴大1倍ATR
- **大盤氛圍濾網**：用0050(元大台灣50)相對120日均線的位置，空頭氛圍時停用做多訊號，多頭氛圍時停用做空訊號
- **停損冷卻期**：同一檔股票停損出場後，5個交易日內不再對它重新進場，避免來回被巴
- **結算日過濾**：結算日前1-2天不開新倉（用「當月第三個星期三」近似，可能有國定假日順延造成的1天誤差）
- **保證金查表**：用期交所官方320檔標的清單(`taifex_universe.py`)查證哪些股票真的有期貨、有沒有小型契約，不再用股價門檻猜測；單筆交易保證金超過本金35%就自動跳過該候選

### 兩個維度的比較：短線 vs 中期、純多 vs 多空雙向

`compare_mean_reversion.py` 會自動跑4種組合：

| | 純多 | 多空雙向 |
|---|---|---|
| 短線版(3-5天持有) | ✓ | ✓ |
| 中期版(約15個交易日持有) | ✓ | ✓ |

### 樣本內/樣本外驗證，避免參數過度配適

回測資料會自動切成前70%（樣本內，用來看策略邏輯有沒有大致合理）跟後30%（樣本外，比較誠實的驗證），
**報告裡樣本外的數字才是比較值得信任的參考依據**，樣本內數字容易受到參數剛好適合那段歷史的巧合影響。

### 怎麼跑

跟前兩套回測完全一樣的操作方式：

1. 把 `taifex_universe.py`、`mean_reversion_engine.py`、`compare_mean_reversion.py` 上傳到倉庫最外層
   （**`data_loader.py` 這次也更新了，記得一併覆蓋上傳**，因為新增了支援320檔全市場格式的邏輯）
2. `.github/workflows/mean_reversion_backtest.yml` 用「Create new file」建立，檔名要打完整路徑
3. Actions 分頁選 **"Run Mean Reversion Backtest"** → Run workflow
   - `max_stocks` 建議第一次先設 `50` 測試流程有沒有跑得動，確認沒問題後再改成 `0`（全部320檔，會跑比較久）
4. 完成後下載 `mean-reversion-results` artifact
5. 解壓縮看 `summary.txt`（樣本內外、4種組合並排比較）跟 `oos_equity_curve.png`（樣本外的4條權益曲線）

### 這次額外要誠實揭露的限制

- **結算日用近似規則**：「每月第三個星期三」，若該月因國定假日順延，可能有1天誤差
- **假日不需要額外處理**：yfinance本來就不會回傳休市日資料，回測walk-forward天生跳過假日，不影響回測準確性；但這跟「即時交易機器人main.py」不一樣，那個是靠固定排程跑，需要另外判斷今天是否為交易日，這是兩個不同的問題
- **大盤氛圍濾網用0050代理，不是直接用加權指數**：兩者高度連動但不完全相同
- **保證金比例表只有部分股票有查證過精確數字**，其餘用20%保守估計值頂替，寧可少選一些股票也不要低估風險，正式使用前應該以期貨商當下公告為準
- **倖存者偏差**：用「現在」期交所的320檔標的清單回測過去幾年，會漏掉這段期間已經下市/下架的期貨標的
- **跌停鎖死、除權息、法說會、注意股/處置股**這幾項我們討論過要納入的規則，這個版本**還沒有實作**，是已知的待補項目，目前的回測數字沒有反映這些真實限制的影響

## 八、右側順勢突破雙向策略（新，跟均值回歸相反方向的進場邏輯）

均值回歸(七)是「逢低承接」，這套是反過來的「右側/順勢」：只在真正突破(有量、有相對強弱、
站上結構)時才進場，不是逢超跌承接。標的、部位執行、風控框架(保證金查表、結算日濾網、
停損冷卻期、大盤氛圍濾網)都跟均值回歸引擎共用，只有「選股邏輯」不一樣。

### 選股邏輯：兩層判斷

1. **結構性門檻**：基本門檻永遠套用(做多=站上20日均線+突破前20日收盤新高；做空對稱)，
   另外有4個可選的額外門檻，可以單獨開關比較效果：
   - **站上季線(60日均線)**——長期趨勢也要偏多，過濾「短線站上但大方向還在空頭」的假突破
   - **均線多頭排列**(MA5>MA20>MA60)——比單一均線更嚴謹的排列確認
   - **爆量門檻**(量比>=可調數值，預設比較組用1.5)——不是隨便超過1倍均量就算，要真的放量
   - **雙法人同步買超**(可選，需要`--with-chip-confirm`)——外資+投信買超比重同時為正(做多)
     或同時為負(做空)才算通過，比單一法人更嚴格
2. **訊號評分(通過門檻的候選裡，依加權分數排名，取前N名)**，目前有10個可搭配的訊號：

   | 分類 | 訊號 |
   |---|---|
   | 技術 | 量比、相對大盤強弱、RSI由下往上穿越50、MACD柱狀圖 |
   | 均線/型態 | 均線黃金交叉/死亡交叉(MA5剛穿越MA20，抓轉折發生的當下)、價量同步創高/創低(比量比更嚴格，要求價跟量同時創極值)、跳空突破(近期是否出現方向一致的跳空缺口)、K棒實體比例(買盤/賣盤主導意願) |
   | 籌碼(可選，需要`--with-chip-confirm`) | 外資買超金額佔成交比重、投信買超金額佔成交比重 |

   這裡查的都是嚴格早於進場日的資料(用`_lookup_prior_row`)，時間點上沒有隔日衝發現的
   「偷看當天籌碼」問題。

### 進場時機診斷（新增：突破窗口比較 / 趨勢強度ADX / 波動收縮後突破）

前幾輪測試把出場機制(移動停利)、部位規模(風險預算式)、市況穩健性(跨週期驗證)都測過一輪之後，
最佳組合的OOS PF、bootstrap p值仍然顯示沒有站得住的優勢，這暗示問題可能出在**進場時機本身**：
固定用「20日創新高」當結構門檻，有可能買在短線衝高、接近拉回的位置，而不是真正趨勢剛起漲的點。
這一輪新增三個直接針對這個假設的診斷工具：

- **突破窗口比較(自動、不需要額外CLI參數)**：`summary.txt`每個持有天數區間最前面會多一段
  「突破窗口比較」，額外測試5日(提早進場)、60日(季線級別)、250日(約52週新高，年線級別)三種
  替代窗口，跟原本20日一起比較(等權重訊號+基本門檻，只在IS內)，自動選總損益最高的窗口，
  後面所有階段(訊號拆解、門檻比較、ATR網格、最終IS/OOS驗證、跨週期驗證)都會改用選出的窗口，
  不再寫死20日
- **趨勢強度門檻(ADX>=25)**：新增的門檻變體之一，只在ADX指標(平均趨向指標，衡量價格趨勢
  強弱，不分方向)達到閾值時才放行，用意是過濾掉盤整雜訊造成的假突破，只在真的有趨勢的時候進場
- **波動收縮後突破門檻**：新增的門檻變體之一，只在近期(10日)平均真實波動幅度%相對前期(20日)
  明顯收縮(比值<=0.85)時才放行，嘗試抓「盤整蓄積後才噴出」的型態，比隨機一天創新高更可信

這兩個新門檻會自動併入既有的「結構門檻變體比較」(階段2)一起排名，不需要額外的CLI參數。

### 「只吃魚身」出場配置比較(新增，僅移動停利模式)

進場時機診斷確認「250日突破+ADX趨勢強度」這個方向後，下一個問題是「抱多久」。有些交易哲學
選擇讓移動停利跑到底(抱到趨勢真正走完，連末升段的洗盤也吃)；但如果目標是短波段、只吃主升段
最兇的那幾天(魚身)，不追最低點(魚頭)、也不奢求抱到最高點(魚尾)，出場配置就要不一樣。這次新增
的「出場配置比較」(`summary.txt`裡的階段2.6)在ATR倍數固定之後，額外比較6種配置:

- **持有天數上限**：加一個強制出場的天數上限(例如10個交易日)，行情一旦走成牛皮盤整，時間到
  就無條件出場，不無限期等下去
- **移動停利延遲啟動**：進場後的前幾天(或還沒累積到一定倍數的ATR獲利之前)只用進場當下設定
  的固定初始停損防守，不提前啟動移動停利，避免「進場後正常的健康拉回」被貼太緊的移動停利
  提前洗出場，魚身都還沒吃到就出局
- **開盤跳空上限**：開盤跳空幅度超過一個正值(例如+2.5%)就放棄進場，跟既有的-0.5%下限方向
  相反，用意是避免追在隔日沖主力已經拉高、獲利空間被追價盤吃乾抹淨的位置

程式會自動選總損益最高的一組，套用在最終驗證的「最佳組合」(對照組不受影響，維持原本固定天數+
立即啟動的移動停利，方便比較)。`summarize_mr()`同時新增了**平均持有天數**這個統計量，
`summary.txt`裡每個IS/OOS結果都會顯示，用來檢查選出的配置有沒有真的抓到預期的短波段長度——
如果平均持有天數還是偏長，代表天數上限或延遲啟動的參數要再調緊；如果偏短(例如不到2天)，
代表移動停利貼得太緊，連健康拉回都被洗出場，不是只洗到真正的反轉。

⚠️ 這裡沒有做、也做不到的部分(誠實揭露)：實盤下單前還要注意的「個股期貨本身的流動性」
(日均量、未平倉量)、以及「期貨結算週期換月」，這兩個我們的資料源(用yfinance抓現貨股價當
股票期貨的近似值)完全沒有涵蓋，回測數字沒辦法反映這兩個風險，下單前要自己另外確認。

### 「相對排名」取代絕對值硬門檻(新增，核心哲學：不追求「準」，追求「賠得少、賺得多、選得穩」)

前幾輪測試把標的池從50~100檔擴大到全市場320檔之後，發現一個規律：既有的量化訊號
(`score_volume_ratio`、`score_rel_strength`、`score_macd`等，全部都是用`percentile_score()`
算出來的相對排名分數)排名相對穩定，但「收盤價一定要站上突破窗口的前高/前低」這個結構性
硬門檻(絕對值判定)，在標的池大小變動時排名震盪很大，甚至讓整套邏輯的優勢消失。這暗示問題
不是訊號本身沒用，而是「用絕對值判定候選資格」這件事本身對標的池大小、期間長短太敏感——
相對排名不管拿去跟多少檔股票比較，永遠是「矮子裡拔將軍」，不會因為多了幾百檔冷門股就突然
篩不出任何候選，或篩出完全不同的一批。

這一輪新增兩個機制，把這個觀察落實成可以實測的選擇：

- **`score_breakout_strength`(突破強度，連續分數)**：不再只問「有沒有突破」(是/否二元判定)，
  改算「離突破窗口高/低點還差幾倍ATR」的連續距離，再用跟其他訊號一樣的相對排名方式打分數——
  這樣「差一點點就突破」跟「已經突破一大截」在排名上會有合理的區別，而不是差一檔就被硬門檻
  整批擋在外面
- **突破風格比較(新增的「階段0.7」，`summary.txt`裡突破窗口比較之後的新表格)**：直接測試
  「硬門檻(舊版，收盤價一定要>突破窗口高/低點)」vs「軟性排名(只留最基本的「站上/跌破20日
  均線」當結構性資格，突破強度完全交給`score_breakout_strength`的相對排名去決定候選順序)」
  哪一種總損益比較高，自動選出來的風格會固定套用到後面所有階段(訊號拆解、門檻比較、ATR網格、
  最終IS/OOS驗證、跨週期驗證)，不需要額外的CLI參數。

同時修正了一個上一輪發現、影響結果可信度的方法論問題：**ATR敏感度網格(階段2.5)跟出場配置
比較(階段2.6)過去內部寫死用固定2口下單，沒有套用`--risk-pct-per-trade`/
`--max-concurrent-positions`這兩個實際下單會用到的部位大小設定**，導致「篩選階段選出的最佳
ATR倍數/出場配置」跟「最終驗證階段實際套用的部位大小」不是同一套規則——風險預算式部位大小
在停損距離較大時可能算出0口而跳過某些交易，篩選階段用固定2口測出來的「最佳」組合，換算成
風險預算式部位大小後不一定還是最佳。這一輪把這兩個函式都改成接收真正的執行參數，確保篩選
跟最終驗證是同一套部位大小規則下比較出來的結果，不是拿蘋果的排名去套用到橘子上。

⚠️ 這仍然是**待驗證的假設**，不是先驗認定「相對排名一定比絕對值硬門檻好」——`summary.txt`
會誠實印出兩種風格實測的PF/總損益，程式選總損益較高的那個，但如果軟性排名的PF也不理想，
一樣要誠實地報告「這個方向也沒有站得住的優勢」，不會因為理論上聽起來合理就假設它一定有效。

### 怎麼跑

1. 把 `momentum_breakout_engine.py`、`mean_reversion_engine.py`、`compare_breakout.py`、
   `robustness_analysis.py` 上傳到倉庫最外層(覆蓋/新增)
2. `.github/workflows/momentum_breakout_backtest.yml` 用「Create new file」建立(或覆蓋)，
   檔名要打完整路徑
3. Actions 分頁選 **"Run Momentum Breakout Backtest"** → Run workflow
   - `max_stocks` 建議第一次先設 `50`
   - `with_chip_confirm` 設 `true` 才會測外資/投信買超比重、以及「雙法人同步買超」門檻，
     預設 `false`(跑比較快)
   - `clean_ex_dividend` 設 `true` 會額外下載除權息日期資料，把除權息當天的股票排除在
     候選之外，避免機械性跳空污染量比/相對大盤強弱/突破前高這些訊號，預設 `false`
   - `use_trailing_stop` 設 `true` 時，出場改用**移動停利**：不設固定停利目標價、也不設
     固定持有天數，出場完全交給「碰到初始停損，或行情往有利方向走、停損跟著移動」，
     讓真正延續的趨勢可以抱得比原本5天/中期15天硬上限長很多——這是右側/順勢交易
     「讓獲利奔跑」的核心精神。開啟後原本的短線5天/中期15天兩組比較會被單一的移動停利
     模式取代，且會多跑一段**ATR倍數敏感度網格**(見下)。預設 `false`(維持原本固定天數+
     固定ATR停利)
   - `atr_stop_mult`(初始停損ATR倍數)、`trailing_atr_mult`(移動停利ATR倍數，留空代表
     跟初始停損用同一個值)：非移動停利模式下就是實際套用的倍數；移動停利模式下只用在
     「對照組」，真正驗證的「最佳組合」倍數會由ATR敏感度網格自動搜出，不受這兩個輸入影響
   - `slippage_pct`：進場、以及停損/跳空停損這類市價出場，套用的滑價百分比(例如`0.002`
     代表0.2%)，模擬真實成交價比理論價位差一點的狀況，留空或`0`代表不模擬
   - `max_concurrent_positions`：最佳組合最終驗證時允許同時持有的最大部位數，預設`1`
     (一次一個部位，跟舊版行為一致)，設`3`之類的數字代表最多同時持有3檔不同標的
   - `risk_pct_per_trade`：設定後，最佳組合的口數改用「帳戶權益 x 這個比例 ÷ 停損距離」
     反推(風險預算式部位大小)，不同波動度的標的不會用同樣口數扛不一樣的風險，帳戶權益
     也會隨已實現損益動態調整。留空代表維持固定2口
   - `multi_period_test` 設 `true` 會額外把驗證出的最佳組合套到2022年修正段、2021下半年
     ~2022年初盤整段這兩個跟近期多頭明顯不同市況的歷史期間，檢查是不是只吃到牛市紅利
     (會多跑久一點，因為要多下載兩段資料)
   - `walkforward_folds`：走勢前進(Walk-Forward)分折驗證的折數，`0`(預設)代表不啟用，維持
     原本單一次IS/OOS切分的行為完全不變。設`3`之類的數字會多跑一個獨立的階段，詳見下面
     「走勢前進(Walk-Forward)分折驗證」這一節
4. 完成後下載 `momentum-breakout-results` artifact，看 `summary.txt`，依序看幾段：
   - **突破窗口比較**：5/20/60/250日創新高這幾種進場時機哪一種總損益比較高，程式會自動選出
     最佳窗口，後面所有階段都改用這個窗口
   - **單一訊號拆解**：哪些訊號單獨測PF(獲利因子)明顯>1，代表真的有預測力
   - **結構門檻變體比較**：哪一種額外過濾條件篩出的候選PF比較高
   - (移動停利模式)**ATR倍數敏感度網格**：哪組初始停損/移動停利倍數PF最高
   - **對照組 vs 最佳組合，IS vs OOS + bootstrap**：「最佳組合」是程式依上面幾段結果
     自動選出來的訊號+門檻+ATR倍數組合，不是隨便挑的；如果標示「探索性選擇」，代表
     這次測試沒有任何訊號真正驗證通過(PF>1)，結果僅供參考。OOS的PF、bootstrap正報酬
     比例、p值(越接近0代表優勢在不同交易順序下都站得住，超過0.2以上不該當作已驗證的優勢)
     才是比較誠實的參考依據
   - (`multi_period_test=true`時)**跨市場週期驗證**：最佳組合套到2022年修正段/盤整段的
     PF跟bootstrap正報酬比例，用來判斷這組優勢是不是只在多頭才成立
   - (移動停利模式)**出場配置比較**：持有天數上限/延遲啟動/跳空上限這幾種「只吃魚身」配置
     哪一組總損益最高、平均持有天數是不是落在預期的短波段長度

### 新增的統計量：Profit Factor(PF，獲利因子)、bootstrap p值

`PF = 總獲利金額 / 總虧損金額(取絕對值)`，>1代表賺的比賠的多，<1代表賠的比賺的多，跟
勝率不同的地方是PF不受交易筆數多寡影響，可以跨組合比較。`summary.txt`裡每一個表格都會
顯示PF，∞代表這組測試完全沒有虧損交易(通常是交易筆數太少的警訊，不是真的沒有風險)。
除了PF，`summarize_mr()`回傳的字典裡還多了`max_consecutive_losses`(最大連續虧損筆數)、
`sharpe_like`/`calmar_like`(簡化版、非年化的比率，不是教科書標準公式)、
`top_trade_pct_of_total_pnl`(單筆最大交易佔總損益的比例)、`pnl_excluding_top3_ntd`
(拿掉獲利最大3筆交易後的總損益)、`avg_hold_days`(平均持有天數，這次新增，用來檢查「只吃
魚身」的出場配置有沒有真的抓到預期的短波段長度)。`robustness_analysis.py`的bootstrap重抽樣結果額外算了
`p_value`(單尾p值，n次重抽樣裡總損益<=0的比例，等於1-正報酬比例/100)，p值越接近0代表
優勢越站得住，超過0.2以上就不該當作已驗證的優勢。

### 誠實揭露的限制

- 跟均值回歸引擎共用的已知限制(結算日近似、大盤氛圍濾網用0050代理、跌停鎖死/
  注意股處置股未實作、倖存者偏差)在這裡一樣成立
- 這10個訊號、4個額外門檻，除了量比/相對大盤強弱之外，**都是第一次接上測試**，還沒被
  任何歷史資料驗證過，跟已經在隔日衝那邊反覆驗證過的量比/相對大盤強弱不是同一個可信度等級
- 第一輪、第二輪測試(4訊號/1門檻、10訊號/5門檻，都用固定天數+固定ATR停利出場)結果都是
  全面虧損。台股今年從年初約30,000點漲到約48,000點，右側/順勢交易理論上應該非常有優勢，
  這個矛盾指向真正的問題很可能不是訊號本身沒用，而是**出場設計**：固定5天/15天強制出場、
  固定ATR停利，是從均值回歸引擎(設計成「小賺快跑」)直接沿用過來的，跟右側交易「讓獲利奔跑」
  的核心精神互相矛盾。這次新增的移動停利模式(`use_trailing_stop`)就是為了驗證這個假設——
  如果訊號本身有效，換掉出場機制後表現應該會明顯不同；如果換了出場還是全面虧損，才比較能
  排除「是出場設計的問題」，回頭懷疑訊號或門檻本身
- **跳空穿越停損的真實成交價**：如果進場當天開盤價已經跳空穿越理論停損價，回測會假設
  用開盤價成交(`stop_gap`事件)，不是假設能用理論停損價成交，比原本的假設更保守、更真實，
  但仍然沒有模擬保證金追繳/強制斷頭的完整流程(維持率、追繳通知、強制平倉的時間差都沒有模擬)
- **除權息缺口清洗**(`--clean-ex-dividend`)是用「排除當天候選」而不是「調整股價」來處理，
  因為調整股價會讓回測的進出場價位跟真實可成交的期貨報價脫節；不開啟這個選項時，除權息當天
  的機械性跳空還是有可能被誤判成真正的動能轉強或轉弱
- **穩健性檢查(bootstrap)**是簡化版方法，沒有考慮交易之間的時間相關性(例如連續虧損可能不是
  隨機獨立發生的，可能整段時間市場環境就是不利)，只能當作參考，不是嚴謹的統計推論
- **多重比較問題**：測了10個訊號 x 5種門檻 x(移動停利模式下)6組ATR倍數，挑「看起來最好」
  的那組，本質上有一定機率只是雜訊湊巧對到這段歷史。程式會自動用IS結果選出「最佳組合」，
  但選出來的組合仍然只在OOS驗證過一次，不是嚴謹的統計顯著性檢定——這也是為什麼要看
  bootstrap的p值、以及(建議加開)跨市場週期驗證，而不是只看單一個PF數字
- **滑價假設是簡化的固定比例**，只套用在進場跟停損類的市價出場，沒有隨盤中真實流動性、
  成交量、標的波動度動態調整，實務上流動性差的標的滑價可能遠不只這個比例
- **多部位並行的保證金/資金配置仍是簡化模型**：`max_concurrent_positions>1`時，個別部位
  保證金上限維持35%總資金，另外加一個「所有持倉保證金總和」的整體上限(預設抓
  `min(35% x 並行部位數, 90%)`)，但沒有模擬真正券商的動態維持率計算、也沒有模擬持倉之間
  的相關性風險(例如3個部位剛好都是同產業，同漲同跌，實際風險集中度比模型算出來的更高)
- **風險預算式部位大小(`risk_pct_per_trade`)沒有考慮標的之間的相關性**，只針對單一部位的
  停損距離反推口數，如果多個並行部位的標的同漲同跌，加總起來的實際風險會比「每筆風險都是
  帳戶權益的X%」這個假設更高
- **跨市場週期驗證(`multi_period_test`)不是嚴謹的IS/OOS切分**，只是把已經選定的組合原封
  不動套到另一段歷史期間跑一次，如果那段期間表現也不好，只能說「這組合在那段市況表現不好」，
  不能反過來說「如果拿那段期間重新篩選訊號，結果會一樣」——不同市況下最有效的訊號組合本來
  就可能不一樣，這裡沒有對每段期間分別重新篩選
- **ADX採用近似算法**：用`ewm(alpha=1/period, adjust=False)`模擬Wilder平滑，不是課本上的
  精確遞迴公式，數值會有些微差異，但方向性(趨勢強/弱的相對排序)是一致的
- **突破窗口比較只在IS內選一次，跟訊號/門檻選擇疊在一起，多重比較問題又更嚴重一層**：
  窗口x訊號x門檻x(移動停利模式下)ATR倍數是四層疊加的搜尋，挑出來的「最佳組合」統計上
  比單一層次的搜尋更容易只是雜訊湊巧對到這段歷史，OOS/bootstrap驗證的重要性因此更高
- **這一輪明確沒有做的事(留給下一輪)**：均線動態停利(取代固定ATR移動停利)、Chandelier停利
  錨點(用區間高/低點而非收盤價當基準)、拉回測試型進場(不是創新高當天進場，而是等突破後拉回
  測試支撐才進場，架構上是狀態機，跟現在「單日掃描+進場」的方式不同)、類股輪動/市場廣度濾網
  (需要新的產業分類/大盤廣度資料)、分批加碼/減碼(需要部位可以拆分的引擎支援)——這些如果之後
  要做，都需要先把預先算好的指標值一路傳進共用的逐日出場處理函式(`_process_mr_day`/
  `update_trailing_stop`)，目前那些函式只看得到原始OHLCV，還沒有指標值可以用

### 順勢交易再設計：MA5+均線型態、訊號組合比較、保本停損(新增)

這一輪是使用者根據自己的盤感直接提出的三個新假設，核心想法是「短波段順勢交易」：
不要跟大盤逆勢、抓主力進場的痕跡、有賺就先保本、不要凹單凹到反虧。三個都是**還沒被驗證過的
新假設**，程式只負責誠實測出PF/總損益排名，不會因為背後邏輯聽起來合理就假設它一定有效。

- **訊號組合比較(`summary.txt`裡新增的「階段1.5」)**：既有的「單一訊號拆解」機制只驗證單一
  訊號的個別預測力(逐一測`score_macd`、`score_rsi_cross`、`score_volume_ratio`...等哪個單獨
  測PF>1)，但使用者提出的假設是「MACD柱狀圖轉正+RSI穿越50+量比放大」三個訊號**組合起來**
  代表「主力進場、散戶跟進、短進短出、最後誰接盤」的现象——量比、RSI單獨測往往測不到PF>1，
  永遠不會被既有的自動篩選機制選中，但組合起來可能有效(或無效)，這是自動篩選機制結構上
  發現不了的。這一輪新增的階段把「自動篩選出的訊號組合」跟「使用者手動指定的這組固定組合」
  放在一起實測比較，選總損益較高的那組，固定套用到後面所有階段(門檻比較改用選定的組合當
  基準，不再是全部訊號等權重)
- **MA5基礎+均線型態門檻(新增的「結構門檻」變體之一)**：原本的基本方向確認是「收盤價>MA20
  (20日均線)」，這次新增一個變體改用MA5(5日均線)，理由是使用者鎖定短波段交易，MA20反應太慢。
  同時要求額外滿足下列兩者之一(不是硬性都要滿足，是OR的關係)：
  - **均線糾結**：MA5/MA20/MA60三條線貼得夠近，代表盤整蓄勢、有機會醞釀突破——用
    `(三線最大值-三線最小值)/ATR <= 0.5`當門檻(這個0.5倍數是先射後畫的初始設定，還沒
    用歷史資料調過，屬於待驗證的參數選擇)
  - **多頭(或空頭)並列且三線同步走勢**：不只要求MA5>MA20>MA60(多頭時)這個排列順序，
    還要求三條線各自都比5個交易日前的自己高(不是走平或走弱的排列，是真正同步向上的排列)
  這個門檻變體會被放進既有的「結構門檻變體比較」表格裡跟其他門檻(舊版MA20基礎、只看大盤氣氛
  等等)一起比較總損益，不是預設一定會贏
- **保本停損(新增的「出場配置」變體之一，`breakeven_after_profit`)**：回應「只要有漲，
  停利一定是成本價，不要漲了後面下跌還賠錢」這個原則——只要浮動獲利轉正(收盤價漲過進場價，
  空單則是跌破進場價)，就把停損價移到成本價(進場價)，之後只會往有利方向移動，不會退回去。
  這是獨立於既有移動停利(ATR倍數)之外的一道「保本地板」，兩者可以同時生效，取兩者之中對
  部位更有利(停損價更高/更低)的那個。搭配新增的「3天出場+保本停損」出場配置——強制出場天數
  從原本的10天縮短到3天，呼應使用者「短波段、短進短出」的定位，同時拿掉了原本「移動停利延遲
  啟動」機制(因為3天的持有天數上限跟「進場後前幾天不啟動移動停利」邏輯上會互相打架，這一輪
  改成單純「有賺就保本」，不用延遲啟動)

⚠️ 這三個都是使用者盤感提出、還沒被驗證過的新假設。`summary.txt`會誠實印出：(1)自動篩選
組合 vs 手動指定組合，實測PF/總損益哪個較高；(2)MA5+均線型態門檻跟其他門檻比較，PF是不是
真的比較高；(3)3天+保本停損這組出場配置的平均持有天數是不是真的落在預期的短波段長度、
PF有沒有比其他出場配置好。如果實測結果不支持某個假設，會照實報告「這個方向也沒有站得住的
優勢」，不會因為理論上聽起來合理就假設它一定有效。

### 新增7個訊號(籌碼連續買超/主力買賣超多日窗口、MACD背離、5日量增)、跳過融資融券比/家數差、走勢前進(Walk-Forward)分折驗證(新增)

這一輪新增三件事：7個新訊號(2個籌碼連續買超訊號、3個主力買賣超多日窗口訊號、1個MACD背離
近似訊號、1個短窗成交量急增訊號)、明確說明為什麼跳過融資融券比/家數差這兩個使用者提過的
籌碼面訊號、以及一個全新的驗證階段(走勢前進分折驗證，回應「單一次OOS切分是不是運氣好」
這個疑慮)。

**7個新訊號分三組**：

- **籌碼連續買超/賣超天數(2個)**：`score_foreign_streak`(外資連續買超天數)、
  `score_trust_streak`(投信連續買超天數)——正值代表連續買超、負值代表連續賣超(絕對值是
  天數)，抓的是「這個法人是不是持續站在同一邊」，跟既有的外資/投信買超比重(單日金額比重)
  是不同的現象：比重看的是「今天買超力道多強」，連續天數看的是「這個力道有沒有延續性」。
- **主力(外資+投信合計)買賣超強度，1/5/10日三個窗口(3個)**：`score_institutional_net_1d`
  /`_5d`/`_10d`，這就是使用者說的「主力的買賣超」——三個窗口分別看「當天」「近一週」
  「近兩週」外資+投信合計買賣超金額佔成交金額的比重，是同一個現象在不同時間解析度下的
  版本，所以沒有另外設計第4個「主力買賣超」訊號，避免重複計分。
- **MACD背離(近似，1個)**：`score_macd_divergence`——⚠️這是近似實作，不是嚴謹的技術分析
  背離定義。教科書上的背離是找股價的擺盪高/低點(swing high/low)，比較連續兩個擺盪點的
  價格方向跟MACD方向是否一致，這需要峰谷偵測(peak/trough finding)，這個程式裡其他指標
  都是向量化一次算好整個序列，沒有這種逐日狀態機式的演算法，貿然加一個複雜度不成比例。
  這裡改用業界常見的近似做法：直接比較「股價過去20天(可調)的變化」跟「MACD線本身過去
  20天的變化」方向是否背離——多頭背離＝股價這段期間沒漲(或還在跌)，但MACD動能已經開始
  轉強；空頭背離對稱。這比精確定義更容易在盤整區間誤觸發，是待驗證的近似訊號。
- **短窗(5日)成交量急增(1個)**：`score_volume_spike`——既有的`score_volume_ratio`用20日
  均量當分母，抓的是「近期量能持續偏高」；這個新訊號改用5日均量，抓的是「這一兩天突然
  爆量」，是刻意跟20日窗口區隔開的不同現象，不是重複的訊號。

這7個訊號全部會被放進既有的「單一訊號拆解」表格裡一起排名，不會因為背後邏輯聽起來合理
就預設有效。籌碼相關的5個(連續買超天數x2、主力買賣超窗口x3)需要`with_chip_confirm=true`
才會測試，沒有籌碼資料時分數自動歸零(不影響其他訊號)，跟既有的外資/投信買超比重訊號
處理方式一致。

**明確跳過融資融券比/家數差**：使用者也提過這兩個籌碼面訊號，這一輪**沒有**實作，原因是
資料源缺口，不是設計選擇：融資融券比需要另外接證交所「MI_MARGN」信用交易報表，欄位/
端點都跟現在的T86完全不同，需要重寫一整套下載邏輯；家數差(分點進出)在公開資料裡沒有任何
免費的彙整端點，證交所公布的是單一分點等級的明細，要嘛自己彙整數千個分點帳戶的原始交易
明細，要嘛改用付費第三方籌碼商的整理資料，已經超出「直接打政府公開API」的範圍。詳見
`chip_data_loader.py`模組docstring最後一段的完整說明。

### 走勢前進(Walk-Forward)分折驗證(新增)

既有的驗證方式是把整段歷史切一刀，前面當樣本內(IS，用來篩選訊號/門檻/ATR倍數)、後面當
樣本外(OOS，只驗證一次)。這樣的問題是：**只驗證了一次「這組被選出來的答案，套到沒看過的
資料表現如何」**，如果那一次OOS剛好表現好，沒辦法分辨是「這組合真的有效」還是「剛好那段
OOS期間運氣好」。

白話比喻：原本的作法像是「用前面70%的模擬考題庫練出一套解題公式，只考一次正式大考」；
走勢前進分折驗證則是「把整段時間切成好幾輪模擬考+正式大考(像切香腸一樣，一段一段來)，
每一輪都用**當時為止的所有題庫**(擴張視窗，題庫只會越滾越大，不會用到考試當下還沒發生
的未來資料)重新練一次解題公式，再考當下這一輪的正式大考，最後檢查：**每一輪練出來的
解題公式(訊號組合/門檻/出場配置)是不是都差不多？還是每次都換一套？** 如果每輪都選到
差不多的答案，代表這組優勢比較站得住；如果每輪都換一套，代表很可能只是在追每一段歷史
自己的雜訊，不是真正跨時間都成立的優勢。

**怎麼開啟**：GitHub Actions欄位`walkforward_folds`設一個正整數(例如`3`)即可，`0`(預設)
代表不開啟，維持原本單一次IS/OOS切分的行為完全不變，兩種驗證可以在同一次執行裡都跑
(不互斥)。

**預設建議值3折**：這是全新的階段，實際會多花多少時間目前還沒有校準過，而GitHub Actions
先前就遇過3小時以上逾時的狀況，這次的時間預算是~2.5小時，所以保守從3折開始試，之後如果
確認耗時可以接受，再考慮調大。折數不是寫死的，是CLI的一個參數，可以自由調整。

**怎麼讀結果**：`summary.txt`新增一段「走勢前進(Walk-Forward)分折驗證」表格，每一列是一折
的訓練期間/測試期間/選中的訊號組合/門檻/出場配置/測試期表現。表格下面的「[穩定性]」這行
是重點：`N折中出現M種不同的訊號組合被選中`——`M`越接近1代表越穩定(每折都選到差不多的
答案)，`M`越接近`N`代表越不穩定(每折都選到不同答案，比較可能是在追雜訊)；同一行也會列出
各折測試期PF的範圍(min/max/mean)，PF在各折之間差異很大，也是不穩定的訊號。

**兩個明確的簡化/取捨(時間預算考量，誠實揭露，不是忘記做)**：

1. **不會每折重新選一次突破窗口(階段0)跟突破風格(階段0.7)**，這兩項選定的結果直接沿用
   外層(用完整歷史選一次)的答案，套用到所有折。這裡驗證的是「訊號/門檻/出場配置」的
   跨時間穩定性，不是「突破窗口/突破風格」的穩定性——這是一個判斷(這兩者對市場regime
   的敏感度理論上比訊號權重/門檻組合低)，不是實測結果，如果之後要驗證這兩項本身的
   穩定性，需要再擴充。
2. **每折固定用移動停利模式跑**(ATR敏感度網格+出場配置比較這兩個階段本身就只在移動停利
   模式下有意義)，不管有沒有加`--use-trailing-stop`。這是因為走勢前進驗證的核心正是想看
   「出場配置(天數上限/延遲啟動/跳空上限/保本停損)」選擇的穩定性，固定天數模式沒有這些
   可比較的維度。
3. 資料下載跟指標precompute只做一次(重複使用main()已經對完整歷史算好的結果)，每一折
   只是換一段日期去呼叫已經不需要網路的比較函式，這是符合時間預算的關鍵設計——如果
   每折都重新下載/precompute，運算量會隨折數線性增加，很容易再度逼近3小時逾時的狀況。

## 五、重要限制（誠實告知，不要照單全收）

1. **停損/停利同一天觸發時的判定是保守假設**：如果同一天內盤中股價曾經跌破停損、又曾經漲過停利，
   回測程式會假設「先跌破停損」，因為只有日K的高低點資料，沒有辦法知道分時走勢的真實先後順序。
   這個假設對原版跟新版是一致的，所以不影響兩版之間的相對比較，但代表回測結果本身可能比實盤更保守一點。
2. **用「當日開盤價」模擬即時報價**：正式程式是抓盤中即時報價來判斷跳空風控，
   回測沒有那麼細的資料，改用當日開盤價當作近似值。
3. **回測不等於未來會賺錢**：這個工具只能告訴你「如果過去用這套邏輯操作會發生什麼事」，
   不代表策略本身是穩賺不賠的，過去績效不代表未來表現。
