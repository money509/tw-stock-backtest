# 台股策略回測比較工具

比較「原版（ATR計算有bug）」跟「新版（ATR計算已修正）」這兩套邏輯，
用同一份歷史股價回測，看修正 ATR 公式對策略績效實際上造成多大差異。

兩個版本的**進場條件完全一樣**（均線多頭排列、跳空風控），差別只在停損/停利價位的計算方式，
所以績效差異可以完全歸因於 ATR 公式的修正，不會被其他因素干擾。

---

## 一、檔案說明

| 檔案 | 用途 |
|---|---|
| `engine.py` | 回測核心邏輯（跟 `main.py` 的策略邏輯保持一致） |
| `data_loader.py` | 從 Yahoo Finance 下載歷史股價，並存成本機快取 |
| `compare.py` | 主程式，跑兩種版本並輸出比較報告 |
| `requirements.txt` | 需要安裝的 Python 套件清單 |

## 二、怎麼在本機執行（最簡單、不用 GitHub）

如果你只是想先在自己電腦上跑跑看，**不需要建立 GitHub 專案**，照下面步驟做就好：

### 步驟 1：安裝 Python

如果電腦還沒有 Python，先到 https://www.python.org/downloads/ 下載安裝（3.10 版以上）。
安裝時記得勾選 **"Add Python to PATH"** 這個選項。

### 步驟 2：把這幾個檔案放進同一個資料夾

例如放到桌面的 `stock-backtest` 資料夾裡，確認 `engine.py`、`data_loader.py`、`compare.py`、
`requirements.txt` 都在同一層。

### 步驟 3：安裝套件

打開終端機（Windows 叫「命令提示字元」或 PowerShell，Mac 叫「終端機 Terminal」），
切換到那個資料夾，輸入：

```bash
cd 桌面/stock-backtest
pip install -r requirements.txt
```

### 步驟 4：執行回測

```bash
python compare.py
```

預設會抓「最近兩年」的資料。想指定期間可以加參數，例如：

```bash
python compare.py --start 2022-01-01 --end 2025-01-01
```

第一次執行會需要一點時間下載約 60 檔股票的歷史資料，之後重複執行會用本機快取，速度快很多。
如果想強制重新下載最新資料：

```bash
python compare.py --refresh
```

### 步驟 5：看結果

執行完會在同一個資料夾下產生一個 `results/` 資料夾，裡面有：

- `summary.txt`：兩版績效比較表格（交易次數、勝率、平均報酬、累積報酬、最大回撤）
- `trades_buggy.csv`：原版每一筆交易明細，可以用 Excel 打開
- `trades_correct.csv`：新版每一筆交易明細
- `equity_curve.png`：兩版權益曲線比較圖，用看圖檔軟體打開就能看到走勢對比

## 四、如何解讀報告裡的數字

| 指標 | 意義 |
|---|---|
| 交易次數 | 這段期間總共進出場幾次 |
| 勝率 | 賺錢的交易佔全部交易的比例 |
| 平均每筆報酬 | 每一筆交易平均賺/賠多少百分比 |
| 累積報酬 | 假設本金固定投入、連續做這些交易，總共累積賺/賠多少（不含資金運用效率） |
| 最大回撤 | 從最高點到最低點，資金曾經縮水過的最大幅度，數字越負代表風險越大 |

## 六、動能分數 x 部位大小：四種組合比較（進階）

除了ATR公式的比較，這裡再多提供一組比較：**動能分數公式**（原版 vs 加入成交量權重）
交叉 **部位大小規則**（固定2口 vs 依風險動態調整口數），一共4種組合。

這4種組合都是建立在「ATR已經修正過」的基礎上（因為那已經確認是對的），
這樣才能單純比較「動能分數」跟「部位大小」這兩個維度各自的影響，不會被ATR那個問題混在一起看不清楚。

### 4種組合分別是什麼

| 組合 | 動能分數 | 部位大小 |
|---|---|---|
| original + fixed2 | 現價/5日線 × 10（原版） | 固定買2口 |
| original + risk_based | 現價/5日線 × 10（原版） | 依風險金額動態換算口數 |
| volume_weighted + fixed2 | 原版分數 × 成交量權重 | 固定買2口 |
| volume_weighted + risk_based | 原版分數 × 成交量權重 | 依風險金額動態換算口數 |

**量能加權公式**：原本分數 × min(當日成交量 ÷ 20日均量, 2.0)。
用「封頂2倍」是為了避免單一天成交量異常暴增，把分數推得不合理的高。

**風險動態調整口數**：設定一個「每筆交易願意賠多少錢」的風險金額（預設NT$20,000），
用 風險金額 ÷ (進場價−停損價) ÷ 契約乘數 反推可以買幾口，且至少維持2口。
這樣波動小的股票可以買比較多口，波動大的股票口數會被限制在比較少，
是比「不管股票波動大小都固定買2口」更接近「風險平衡」的做法。

### 怎麼跑（跟前面ATR比較的方式一樣，用GitHub Actions最簡單）

1. 把 `sizing.py`、`compare_four_way.py`、`.github/workflows/backtest_four_way.yml`
   這三個檔案一樣用「Add file → Upload files」的方式加到你的GitHub倉庫
   （`sizing.py`、`compare_four_way.py` 放在跟 `engine.py` 同一層；
   `backtest_four_way.yml` 要放在 `.github/workflows/` 資料夾底下，
   上傳時檔名要打完整路徑 `.github/workflows/backtest_four_way.yml`）
2. 到 GitHub 網站的 **"Actions"** 分頁，這次選左邊的 **"Run Strategy Backtest (Score & Sizing)"**
3. 點 **"Run workflow"**，可以順便調整「每筆風險金額」跟「起始資金」這兩個參數，不改也可以直接用預設值
4. 等執行完成，一樣到 **"Artifacts"** 下載 `backtest-four-way-results`
5. 解壓縮後看：
   - `summary.txt`：4個組合的績效數字並排比較（交易次數、勝率、報酬率、新台幣損益、最大回撤）
   - `equity_curve_four_way.png`：4條權益曲線疊在一起看走勢差異
   - `trades_原版名稱__部位規則.csv`：每個組合各自的逐筆交易明細

### 重要提醒

如果你之前上傳過舊版的 `engine.py`，記得**這次要用新版覆蓋掉**，不然新的比較程式會出錯或找不到參數。

## 七、均值回歸雙向策略（新策略，取代原本的順勢突破邏輯）

在確認原本「均線突破」策略長期是虧損的之後，重新設計了一套完全不同性格的策略：
**均值回歸、高勝率、小賺小賠、多空雙向、全市場320檔股票期貨動態掃描**。

### 核心邏輯

- **做多**：RSI(14)跌破30 + 股價跌破布林通道下軌 + 股價仍在60日均線之上（避免真正結構性空頭誤觸發）
- **做空**：條件完全對稱，RSI站上70 + 站上布林上軌 + 股價仍在60日均線之下
- **出場**：目標價是布林中軌(20日均線)，停損是通道邊緣再擴大1倍ATR
- **大盤氛圍濾網**：用0050(元大台灣50)相對120日均線的位置，空頭氛圍時停用做多訊號，多頭氛圍時停用做空訊號
- **停損冷卻期**：同一檔股票停損出場後，5個交易日內不再對它重新進場，避免來回被巴
- **結算日過濾**：結算日前1-2天不開新倉（用「當月第三個星期三」近似，可能有國定假日順延造成的1天誤差）
- **保證金查表**：用期交所官方320檔標的清單(`taifex_universe.py`)查證哪些股票真的有期貨、有沒有小型契約，不再用股價門檻猜測；單筆交易保證金超過本金35%就自動跳過該候選

### 兩個維度的比較：短線 vs 中期、純多 vs 多空雙向

`compare_mean_reversion.py` 會自動跑4種組合：

| | 純多 | 多空雙向 |
|---|---|---|
| 短線版(3-5天持有) | ✓ | ✓ |
| 中期版(約15個交易日持有) | ✓ | ✓ |

### 樣本內/樣本外驗證，避免參數過度配適

回測資料會自動切成前70%（樣本內，用來看策略邏輯有沒有大致合理）跟後30%（樣本外，比較誠實的驗證），
**報告裡樣本外的數字才是比較值得信任的參考依據**，樣本內數字容易受到參數剛好適合那段歷史的巧合影響。

### 怎麼跑

跟前兩套回測完全一樣的操作方式：

1. 把 `taifex_universe.py`、`mean_reversion_engine.py`、`compare_mean_reversion.py` 上傳到倉庫最外層
   （**`data_loader.py` 這次也更新了，記得一併覆蓋上傳**，因為新增了支援320檔全市場格式的邏輯）
2. `.github/workflows/mean_reversion_backtest.yml` 用「Create new file」建立，檔名要打完整路徑
3. Actions 分頁選 **"Run Mean Reversion Backtest"** → Run workflow
   - `max_stocks` 建議第一次先設 `50` 測試流程有沒有跑得動，確認沒問題後再改成 `0`（全部320檔，會跑比較久）
4. 完成後下載 `mean-reversion-results` artifact
5. 解壓縮看 `summary.txt`（樣本內外、4種組合並排比較）跟 `oos_equity_curve.png`（樣本外的4條權益曲線）

### 這次額外要誠實揭露的限制

- **結算日用近似規則**：「每月第三個星期三」，若該月因國定假日順延，可能有1天誤差
- **假日不需要額外處理**：yfinance本來就不會回傳休市日資料，回測walk-forward天生跳過假日，不影響回測準確性；但這跟「即時交易機器人main.py」不一樣，那個是靠固定排程跑，需要另外判斷今天是否為交易日，這是兩個不同的問題
- **大盤氛圍濾網用0050代理，不是直接用加權指數**：兩者高度連動但不完全相同
- **保證金比例表只有部分股票有查證過精確數字**，其餘用20%保守估計值頂替，寧可少選一些股票也不要低估風險，正式使用前應該以期貨商當下公告為準
- **倖存者偏差**：用「現在」期交所的320檔標的清單回測過去幾年，會漏掉這段期間已經下市/下架的期貨標的
- **跌停鎖死、除權息、法說會、注意股/處置股**這幾項我們討論過要納入的規則，這個版本**還沒有實作**，是已知的待補項目，目前的回測數字沒有反映這些真實限制的影響

## 八、右側順勢突破雙向策略（新，跟均值回歸相反方向的進場邏輯）

均值回歸(七)是「逢低承接」，這套是反過來的「右側/順勢」：只在真正突破(有量、有相對強弱、
站上結構)時才進場，不是逢超跌承接。標的、部位執行、風控框架(保證金查表、結算日濾網、
停損冷卻期、大盤氛圍濾網)都跟均值回歸引擎共用，只有「選股邏輯」不一樣。

### 選股邏輯：兩層判斷

1. **結構性門檻**：基本門檻永遠套用(做多=站上20日均線+突破前20日收盤新高；做空對稱)，
   另外有4個可選的額外門檻，可以單獨開關比較效果：
   - **站上季線(60日均線)**——長期趨勢也要偏多，過濾「短線站上但大方向還在空頭」的假突破
   - **均線多頭排列**(MA5>MA20>MA60)——比單一均線更嚴謹的排列確認
   - **爆量門檻**(量比>=可調數值，預設比較組用1.5)——不是隨便超過1倍均量就算，要真的放量
   - **雙法人同步買超**(可選，需要`--with-chip-confirm`)——外資+投信買超比重同時為正(做多)
     或同時為負(做空)才算通過，比單一法人更嚴格
2. **訊號評分(通過門檻的候選裡，依加權分數排名，取前N名)**，目前有10個可搭配的訊號：

   | 分類 | 訊號 |
   |---|---|
   | 技術 | 量比、相對大盤強弱、RSI由下往上穿越50、MACD柱狀圖 |
   | 均線/型態 | 均線黃金交叉/死亡交叉(MA5剛穿越MA20，抓轉折發生的當下)、價量同步創高/創低(比量比更嚴格，要求價跟量同時創極值)、跳空突破(近期是否出現方向一致的跳空缺口)、K棒實體比例(買盤/賣盤主導意願) |
   | 籌碼(可選，需要`--with-chip-confirm`) | 外資買超金額佔成交比重、投信買超金額佔成交比重 |

   這裡查的都是嚴格早於進場日的資料(用`_lookup_prior_row`)，時間點上沒有隔日衝發現的
   「偷看當天籌碼」問題。

### 怎麼跑

1. 把 `momentum_breakout_engine.py`、`mean_reversion_engine.py`、`compare_breakout.py`、
   `robustness_analysis.py` 上傳到倉庫最外層(覆蓋/新增)
2. `.github/workflows/momentum_breakout_backtest.yml` 用「Create new file」建立(或覆蓋)，
   檔名要打完整路徑
3. Actions 分頁選 **"Run Momentum Breakout Backtest"** → Run workflow
   - `max_stocks` 建議第一次先設 `50`
   - `with_chip_confirm` 設 `true` 才會測外資/投信買超比重、以及「雙法人同步買超」門檻，
     預設 `false`(跑比較快)
   - `clean_ex_dividend` 設 `true` 會額外下載除權息日期資料，把除權息當天的股票排除在
     候選之外，避免機械性跳空污染量比/相對大盤強弱/突破前高這些訊號，預設 `false`
   - `use_trailing_stop` 設 `true` 時，出場改用**移動停利**：不設固定停利目標價、也不設
     固定持有天數，出場完全交給「碰到初始停損，或行情往有利方向走、停損跟著移動」，
     讓真正延續的趨勢可以抱得比原本5天/中期15天硬上限長很多——這是右側/順勢交易
     「讓獲利奔跑」的核心精神。開啟後原本的短線5天/中期15天兩組比較會被單一的移動停利
     模式取代，且會多跑一段**ATR倍數敏感度網格**(見下)。預設 `false`(維持原本固定天數+
     固定ATR停利)
   - `atr_stop_mult`(初始停損ATR倍數)、`trailing_atr_mult`(移動停利ATR倍數，留空代表
     跟初始停損用同一個值)：非移動停利模式下就是實際套用的倍數；移動停利模式下只用在
     「對照組」，真正驗證的「最佳組合」倍數會由ATR敏感度網格自動搜出，不受這兩個輸入影響
   - `slippage_pct`：進場、以及停損/跳空停損這類市價出場，套用的滑價百分比(例如`0.002`
     代表0.2%)，模擬真實成交價比理論價位差一點的狀況，留空或`0`代表不模擬
   - `max_concurrent_positions`：最佳組合最終驗證時允許同時持有的最大部位數，預設`1`
     (一次一個部位，跟舊版行為一致)，設`3`之類的數字代表最多同時持有3檔不同標的
   - `risk_pct_per_trade`：設定後，最佳組合的口數改用「帳戶權益 x 這個比例 ÷ 停損距離」
     反推(風險預算式部位大小)，不同波動度的標的不會用同樣口數扛不一樣的風險，帳戶權益
     也會隨已實現損益動態調整。留空代表維持固定2口
   - `multi_period_test` 設 `true` 會額外把驗證出的最佳組合套到2022年修正段、2021下半年
     ~2022年初盤整段這兩個跟近期多頭明顯不同市況的歷史期間，檢查是不是只吃到牛市紅利
     (會多跑久一點，因為要多下載兩段資料)
4. 完成後下載 `momentum-breakout-results` artifact，看 `summary.txt`，依序看幾段：
   - **單一訊號拆解**：哪些訊號單獨測PF(獲利因子)明顯>1，代表真的有預測力
   - **結構門檻變體比較**：哪一種額外過濾條件篩出的候選PF比較高
   - (移動停利模式)**ATR倍數敏感度網格**：哪組初始停損/移動停利倍數PF最高
   - **對照組 vs 最佳組合，IS vs OOS + bootstrap**：「最佳組合」是程式依上面幾段結果
     自動選出來的訊號+門檻+ATR倍數組合，不是隨便挑的；如果標示「探索性選擇」，代表
     這次測試沒有任何訊號真正驗證通過(PF>1)，結果僅供參考。OOS的PF、bootstrap正報酬
     比例、p值(越接近0代表優勢在不同交易順序下都站得住，超過0.2以上不該當作已驗證的優勢)
     才是比較誠實的參考依據
   - (`multi_period_test=true`時)**跨市場週期驗證**：最佳組合套到2022年修正段/盤整段的
     PF跟bootstrap正報酬比例，用來判斷這組優勢是不是只在多頭才成立

### 新增的統計量：Profit Factor(PF，獲利因子)、bootstrap p值

`PF = 總獲利金額 / 總虧損金額(取絕對值)`，>1代表賺的比賠的多，<1代表賠的比賺的多，跟
勝率不同的地方是PF不受交易筆數多寡影響，可以跨組合比較。`summary.txt`裡每一個表格都會
顯示PF，∞代表這組測試完全沒有虧損交易(通常是交易筆數太少的警訊，不是真的沒有風險)。
除了PF，`summarize_mr()`回傳的字典裡還多了`max_consecutive_losses`(最大連續虧損筆數)、
`sharpe_like`/`calmar_like`(簡化版、非年化的比率，不是教科書標準公式)、
`top_trade_pct_of_total_pnl`(單筆最大交易佔總損益的比例)、`pnl_excluding_top3_ntd`
(拿掉獲利最大3筆交易後的總損益)。`robustness_analysis.py`的bootstrap重抽樣結果額外算了
`p_value`(單尾p值，n次重抽樣裡總損益<=0的比例，等於1-正報酬比例/100)，p值越接近0代表
優勢越站得住，超過0.2以上就不該當作已驗證的優勢。

### 誠實揭露的限制

- 跟均值回歸引擎共用的已知限制(結算日近似、大盤氛圍濾網用0050代理、跌停鎖死/
  注意股處置股未實作、倖存者偏差)在這裡一樣成立
- 這10個訊號、4個額外門檻，除了量比/相對大盤強弱之外，**都是第一次接上測試**，還沒被
  任何歷史資料驗證過，跟已經在隔日衝那邊反覆驗證過的量比/相對大盤強弱不是同一個可信度等級
- 第一輪、第二輪測試(4訊號/1門檻、10訊號/5門檻，都用固定天數+固定ATR停利出場)結果都是
  全面虧損。台股今年從年初約30,000點漲到約48,000點，右側/順勢交易理論上應該非常有優勢，
  這個矛盾指向真正的問題很可能不是訊號本身沒用，而是**出場設計**：固定5天/15天強制出場、
  固定ATR停利，是從均值回歸引擎(設計成「小賺快跑」)直接沿用過來的，跟右側交易「讓獲利奔跑」
  的核心精神互相矛盾。這次新增的移動停利模式(`use_trailing_stop`)就是為了驗證這個假設——
  如果訊號本身有效，換掉出場機制後表現應該會明顯不同；如果換了出場還是全面虧損，才比較能
  排除「是出場設計的問題」，回頭懷疑訊號或門檻本身
- **跳空穿越停損的真實成交價**：如果進場當天開盤價已經跳空穿越理論停損價，回測會假設
  用開盤價成交(`stop_gap`事件)，不是假設能用理論停損價成交，比原本的假設更保守、更真實，
  但仍然沒有模擬保證金追繳/強制斷頭的完整流程(維持率、追繳通知、強制平倉的時間差都沒有模擬)
- **除權息缺口清洗**(`--clean-ex-dividend`)是用「排除當天候選」而不是「調整股價」來處理，
  因為調整股價會讓回測的進出場價位跟真實可成交的期貨報價脫節；不開啟這個選項時，除權息當天
  的機械性跳空還是有可能被誤判成真正的動能轉強或轉弱
- **穩健性檢查(bootstrap)**是簡化版方法，沒有考慮交易之間的時間相關性(例如連續虧損可能不是
  隨機獨立發生的，可能整段時間市場環境就是不利)，只能當作參考，不是嚴謹的統計推論
- **多重比較問題**：測了10個訊號 x 5種門檻 x(移動停利模式下)6組ATR倍數，挑「看起來最好」
  的那組，本質上有一定機率只是雜訊湊巧對到這段歷史。程式會自動用IS結果選出「最佳組合」，
  但選出來的組合仍然只在OOS驗證過一次，不是嚴謹的統計顯著性檢定——這也是為什麼要看
  bootstrap的p值、以及(建議加開)跨市場週期驗證，而不是只看單一個PF數字
- **滑價假設是簡化的固定比例**，只套用在進場跟停損類的市價出場，沒有隨盤中真實流動性、
  成交量、標的波動度動態調整，實務上流動性差的標的滑價可能遠不只這個比例
- **多部位並行的保證金/資金配置仍是簡化模型**：`max_concurrent_positions>1`時，個別部位
  保證金上限維持35%總資金，另外加一個「所有持倉保證金總和」的整體上限(預設抓
  `min(35% x 並行部位數, 90%)`)，但沒有模擬真正券商的動態維持率計算、也沒有模擬持倉之間
  的相關性風險(例如3個部位剛好都是同產業，同漲同跌，實際風險集中度比模型算出來的更高)
- **風險預算式部位大小(`risk_pct_per_trade`)沒有考慮標的之間的相關性**，只針對單一部位的
  停損距離反推口數，如果多個並行部位的標的同漲同跌，加總起來的實際風險會比「每筆風險都是
  帳戶權益的X%」這個假設更高
- **跨市場週期驗證(`multi_period_test`)不是嚴謹的IS/OOS切分**，只是把已經選定的組合原封
  不動套到另一段歷史期間跑一次，如果那段期間表現也不好，只能說「這組合在那段市況表現不好」，
  不能反過來說「如果拿那段期間重新篩選訊號，結果會一樣」——不同市況下最有效的訊號組合本來
  就可能不一樣，這裡沒有對每段期間分別重新篩選

## 五、重要限制（誠實告知，不要照單全收）

1. **停損/停利同一天觸發時的判定是保守假設**：如果同一天內盤中股價曾經跌破停損、又曾經漲過停利，
   回測程式會假設「先跌破停損」，因為只有日K的高低點資料，沒有辦法知道分時走勢的真實先後順序。
   這個假設對原版跟新版是一致的，所以不影響兩版之間的相對比較，但代表回測結果本身可能比實盤更保守一點。
2. **用「當日開盤價」模擬即時報價**：正式程式是抓盤中即時報價來判斷跳空風控，
   回測沒有那麼細的資料，改用當日開盤價當作近似值。
3. **回測不等於未來會賺錢**：這個工具只能告訴你「如果過去用這套邏輯操作會發生什麼事」，
   不代表策略本身是穩賺不賠的，過去績效不代表未來表現。
